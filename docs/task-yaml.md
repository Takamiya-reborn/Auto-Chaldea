# 任务 YAML 编写规则

任务配置位于 `assets/task/`。**推荐使用内置标准周回 `flow`**：只写每回合的
技能与选卡，周回外壳自动展开。也可以直接手写 `nodes` 节点图——客制化程度高，
但编写难度大，不做推荐，用于 flow 覆盖不了的特殊流程。
`steps` 是节点命中的子步骤序列，在「标准周回 flow」和「节点图任务」中通用。

> **分辨率要求**：内置模板均以 1280×720 分辨率采集，任务中的 `region` 坐标也以
> 1280×720 为基准，命名坐标点（`Center`、`Enemy1` 等）执行时按实际屏幕尺寸等比缩放。
> 模板匹配不做任何缩放，请将设备（模拟器或真机）分辨率固定为 **1280×720**，
> 其他分辨率下识别会失败。

## 任务级字段

- `task_name`：任务显示名称
- `prerequisite`：任务执行前需要满足的条件，会显示在任务详情区域；支持普通文本和多行文本

## 标准周回 flow（推荐）

周回任务的外壳（助战 → 开始 → 战斗 → 结算）一成不变，已沉淀为内置图模板。
任务文件加 `flow: 标准周回` 后只写每回合的变化部分，加载时展开为节点图
（见下节）。连刷次数不写在任务文件里，由 UI 的「执行次数」输入驱动：
一次图执行 = 一轮完整周回。完整示例见 `assets/task/日常虐菜.yaml`。

```yaml
task_name: 日常虐菜
prerequisite: 1号位所长，2号位摩根，三号位杀狐，御主穿CD服
flow: 标准周回
turns:
  1: # 每回合一个条目，键 = 回合序号，必须从 1 连续编号
    skills:
      - pool: 2 # → 技能池/skill_2（region 默认 下），双击加速动画播放
      - pool: 3
        index: 1 # 第 2 个匹配
        target: 摩根/冬之女王 # 子步骤：→ 角色池/摩根/冬之女王（选目标 + 中央点击）
      - master: 1 # 御主菜单第 1 个技能：图标单击开菜单 + Master1 坐标直击
    cards: # 3 个选卡槽位，每个槽位一次识别点击；解析到 cards 自动先点右下角攻击
      - np: 既已过去的人理之终 # 宝具槽位 → 宝具/<名>
      - [buster, arts] # 目标范围：点范围内屏幕最靠前的一个命中
      - [buster, arts, quick] # 最后一张兜底全色卡
```

### 技能条目字段

- `pool` / `master`：二选一。`pool` 为技能池模板序号，条目 region 默认 `下`；`master` 取 `1` / `2` / `3`，为御主菜单里的第 N 个技能，展开为御主技能图标单击（模板 `基本/御主技能`，打开菜单，region 默认 `右`）+ 命名坐标点 `Master<N>` 直接点击——御主技能位置固定，不走模板识别，坐标在 `task_executor.py` 的 `NAMED_POINTS` 中以 1280×720 为基准填写。region 均可在条目里覆盖（`master` 的 `region` 作用于图标识别）
- `const`：常量基础步骤——无识别的固定点击，值为命名坐标点（`Enemy1`、`Center` 等），原样透传为单次点击，不参与动画加速分派
- `target`：可选的子步骤字段（挂在 pool / master 条目上）：本体单击打开目标菜单后，紧接单击 `角色池/<名>` 选目标，再补一次中央点击加速动画播放
- `index` / `region` / `threshold`：与子步骤语法一致，原样透传（`const` 条目不适用）
- `center`：显式覆盖动画加速方式（见下表），取 `double` / `tap` / `none`，或布尔值（`true` → `tap`，`false` → `none`）

### 回合条目字段

- `skills`：技能条目列表，按序执行（见上「技能条目字段」）
- `cards`：选卡槽位列表，每回合最多 3 个（宝具占其一），每个槽位一次识别点击，按列表顺序执行。槽位三种写法：字符串（单一目标 → `基本/<名>`）、数组（目标范围，`multi` 模式点屏幕最靠前的一个命中）、映射（宝具 `np: 名称` → `宝具/<名>`）。已选中的卡出现选中标记后置信度下降不再命中，槽位间的候选范围可安全重叠。解析到 `cards` 即自动先点击右下角攻击按钮进入选卡，无需显式配置，个别界面差异用 `attack_region` 字段覆盖

### 动画加速规则（自动分派）

`Center` 点击是加快动画播放用的，不是游戏确认按钮。技能条目的点击方式按下列规则自动分派，无需手写中央点击：

| 条目类型                 | 点击方式                       | 原因                                           |
| ------------------------ | ------------------------------ | ---------------------------------------------- |
| 无 target 的 pool 条目   | 双击                           | 第一击触发技能，第二击加速动画播放             |
| master 条目（无 target） | 双击 `Master<N>`               | 第一击使用御主技能，第二击加速动画播放         |
| 带 target 的技能条目     | 本体单击；target 单击 + Center | 本体只是打开目标菜单；动画在选完目标后才开始播 |
| const（常量步骤）        | 单击                           | 固定点击，无动画可加速                         |
| `center: tap` 显式覆盖   | 单击 + Center                  | 个别界面需要手动补中央点击                     |

## 节点图任务（手写，进阶）

一般任务用 `flow` 即可；本节语法用于 flow 覆盖不了的特殊流程，也是 flow 展开
的目标形态。

节点 = 一个画面（识别 + 动作），`next` = 有序候选列表——一帧截图按序尝试候选，
先命中谁走谁。"接下来做什么"由当前画面决定，而不是步骤顺序（借鉴 MAA
ProcessTask 的循环语义）。

```yaml
task_name: 图任务示例
prerequisite: 需要准备指定从者和御主礼装
entry: [选助战]
nodes:
  选助战:
    template: 助战池/选助战
    region: 右
    max_times: 3
    exceeded_next: []
    next: [开始任务]
  开始任务:
    template: 基本/开始任务
    region: 右下
    timeout: 3
    next: [战斗]
  战斗:
    template: 基本/attack
    region: 右下
    action: none
    steps:
      - template: skill_1.png
      - template: Center
    next: [战斗, 结算]
  结算:
    template: 基本/请点击游戏界面
    region: 下
    next: [结算, 下一步]
```

### 节点字段（除 template 外全部可省略）

- `template`：识别模板；缺省时为无条件节点（如命名坐标点），只能放在候选列表末尾
- `region` / `index` / `threshold`：识别区域、点击第几个匹配、匹配阈值，与子步骤语法一致（`threshold` 默认 `0.7`）
- `action`：`click`（默认，点击识别到的目标）/ `none`（只识别，配合 `steps`）
- `click`：命名坐标点（`Center`、`enemy1` 等），无识别直接点击；只在无 `template` 的节点上生效
- `steps`：命中后按子步骤语法顺序执行的子步骤（复用 `task_executor`）
- `next`：候选下一节点列表（一帧截图按序尝试）
- `on_error_next`：出错路由（子步骤失败 / 等待超时且无可选节点），用于自救
- `max_times` / `exceeded_next`：本节点最多命中次数；到达后再出现则走 `exceeded_next` 而不执行动作
- `timeout`：等待本节点的秒数；超时视为"已处理"，直接前往其 `next`（可选节点语义，与子步骤 `timeout` 一致）
- `pre_delay` / `post_delay`：动作前 / 后的等待秒数

### 子步骤语法

节点 `steps` 命中后按顺序执行，每步定义一次识别与动作：

```yaml
steps:
  - template: attack.png
  - template: Center
  - template: skill_1.png
    index: 1
    region: "0, 0, 1280, 720"
    step_interval: 1.0
    timeout: 30
  - template: buster,arts,quick
    mode: multi
    count: 2
```

### 步骤字段说明（除 template 外全部可省略）

- `template`：模板图片文件名，默认从 `assets/template/` 中查找；也支持内置命名坐标点，执行时统一解析为固定坐标点击（跳过模板识别）：
  - `Center`：屏幕中心
  - `Enemy1` / `Enemy2` / `Enemy3`：预设的敌人位置，坐标在 `task_executor.py` 的 `NAMED_POINTS` 中以 1280x720 为基准填写，执行时按实际屏幕尺寸等比缩放
  - `Master1` / `Master2` / `Master3`：御主菜单里的三个技能位置，同样在 `NAMED_POINTS` 中配置；标准周回 flow 的 `master: N` 条目展开时自动使用
  - 命名坐标点也可与普通模板混用在 `multi` 模式的逗号列表中，如 `Enemy1,Enemy2,Enemy3`，解析时拆分为先点击坐标、再识别模板的独立步骤
- `mode`：识别模式，默认 `single`；`multi` 表示同时匹配多个模板, 例如：要在三色卡中任选几张、在不同狗粮中任选20张；`none` 只识别并等待模板出现，不执行点击，适合等待开始标志
- `count`：在 `multi` 模式下，重叠去重后按屏幕位置（上→下、左→右）取前 `count` 个结果依次点击
- `index`：同屏多个匹配时的点击顺序，默认取第一个匹配
- `region`：识别区域，可传 `x1, y1, x2, y2`，也支持 `左`、`右`、`上`、`下`、`左上` 等别名
- `step_interval`：点击成功后等待多久再进入下一步，默认约 `1.0` 秒
- `timeout`：单步识别超时，超过后步骤失败（子步骤失败会触发节点 `on_error_next`）
- `retry_interval` 和 `max_retry_interval`：未匹配到目标时的重试间隔与上限（默认 `0.2` 起步、按 2 倍退避、封顶 `3.0`）
- `double`：`true` 时双击——第一击触发，第二击落在动画播放中加速播放（间隔约 `0.1` 秒）；标准周回 flow 展开时自动生成

### 路由与校验规则

- 每轮访问取一帧截图，按序扫描候选节点，命中即执行其动作并路由到它的 `next`
- 等待超时时：优先视为"可选节点已处理"（第一个声明了 `timeout` 的候选直接前往其 `next`），否则走第一个候选的 `on_error_next`，都没有则任务失败
- 用户点击"下一步"（跳过）时：与超时同路；连可选节点和自救边都没有时，兜底视为第一个候选已被手动处理、直接前往其 `next`——跳过只推进图，不会终止任务，且一次点击只跳过一次等待
- 点击成功后立即失效帧缓存，下一轮强制重新截屏
- 加载时静态校验：所有边引用的节点必须存在；无条件节点不能出现在候选列表中间（它不识别就命中，会短路后面的候选）；不可达节点只告警不阻止运行
- `max_times` 到达后节点不再执行动作，仅按 `exceeded_next` 路由；`exceeded_next` 为空列表表示"当它不存在"

## 逃生门

- 任务同时写了 `flow` 和 `nodes` 时以手写 `nodes` 为准（不展开 flow，仅打印提示）
- 非 `标准周回` 的流程：不加 `flow` 字段，直接手写 `nodes`（见「节点图任务」）
- 周回外壳相同但回合内 DSL 表达不了的操作（如指定助战模板、`mode: none` 等待、
  multi 目标选择），参考 `assets/task/冠位戴冠战/EX II/水VII/双所长奥伯龙1t.yaml`
  手写 `nodes`，战斗子步骤沿用步骤语法
