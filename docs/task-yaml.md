# 任务 YAML 编写规则

任务配置位于 `assets/task/`。**使用内置标准周回 `flow`**：只写每回合的
技能与选卡，周回外壳自动展开。也可以手写 `nodes` 节点图——**节点图仍在
测试研发中，暂不投入使用**，现有任务请一律使用 flow。
`steps` 是节点命中的子步骤序列，在「标准周回 flow」和「节点图任务」中通用。

> **分辨率要求**：内置模板均以 1280×720 分辨率采集，任务中的 `region` 坐标也以
> 1280×720 为基准，命名坐标点（`Enemy1`、`Master1` 等）执行时按实际屏幕尺寸等比缩放。
> 模板匹配不做任何缩放，请将设备（模拟器或真机）分辨率固定为 **1280×720**，
> 其他分辨率下识别会失败。

> **Center 禁写**：`Center`（屏幕中心点击）是内部保留的位置常量，yaml 中
> 不允许编写（节点、子步骤、`const` 均不允许），加载时统一拒绝。
> 动画加速已内化为双击 / 延后双击，不再需要显式的中央点击。

## 任务级字段

- `task_name`：任务显示名称
- `prerequisite`：任务执行前需要满足的条件，会显示在任务详情区域；支持普通文本和多行文本

## 标准周回 flow（推荐）

周回任务的外壳（助战 → 开始 → 战斗 → 结算）一成不变，已沉淀为内置图模板。
任务文件加 `type: flow` 后只写每回合的变化部分，加载时展开为节点图
（见下节）。连刷次数不写在任务文件里，由 UI 的「执行次数」输入驱动，存于
共享状态仓（`remaining` = 尚未开始的轮数）：每次选助战命中开启一轮；结算后
出现连续出击且还有剩余轮数时点击、回到选助战开启下一轮；连续出击未出现或
次数耗尽时，结算链（请点击屏幕 ⇄ 下一步，可交叉循环多次）点完后本次图执行
正常结束。完整示例见 `assets/task/日常虐菜.yaml`。

`troop` 字段（flow 必填）：按位次顺序列出 1-3 名从者（名字或昵称），如
`troop: [所长, 终结的伊丽莎白, 杀狐]`。技能池图标全队通用（多个从者共用
同一张图，同屏会出现多个匹配），因此 `skill` 条目一律按从者位次自动限定
技能栏分区（1/2/3号位区域别名见下文区域列表），条目里**不能**再写
`index` / `region`。同名多副本（自出 + 助战占两个位次）时，技能引用用
`N号位` 前缀消歧：`skill: 1号位所长/2`；从者不在 troop 中时加载即报错。

体力不足处理：连续出击 / 开始任务后游戏判断体力不够时弹出苹果选择窗，
处理方式由执行次数弹窗的「使用苹果」勾选决定，存于状态仓两个互斥键
`use_apples` / `no_apples`——勾选时识别到弹窗按**银苹果优先**（银、金节点
按序扫描）点苹果再点决定补体力，回选助战继续本轮；不勾选时只识别弹窗即经
`end_reason: 体力不足` 正常收束，worker 回退被连续出击消耗的一次剩余轮数
（该轮并未真正开始）并显示实际完成轮数。
任务详情表格首尾固定显示「准备」「收尾」两个锚点行，对应周回外壳节点
（选助战 / 开始任务 / 结算链）的执行进度。

```yaml
task_name: 日常虐菜
prerequisite: 1号位所长，2号位摩根，三号位杀狐，御主穿CD服
troop: [所长, 摩根, 杀狐] # 位次顺序，skill 条目按位次自动限定技能栏分区
type: flow
turns:
  1: # 每回合一个条目，键 = 回合序号，必须从 1 连续编号
    skills:
      - skill: 所长/2 # → 从者档案解析为技能池模板，只扫 1号位分区，双击加速动画播放
      - skill: 所长/3
        target: 奥尔加玛丽/1 # 子步骤：选目标（选目标 + 延后双击）
      - master: 1 # 御主菜单第 1 个技能：图标单击开菜单 + Master1 坐标直击
    cards: # 3 个选卡槽位，每个槽位一次识别点击；解析到 cards 自动先点右下角攻击
      - np: 所长 # 角色引用 → 档案宝具模板；也可直接写宝具模板名
      - [buster, arts] # 目标范围：点范围内屏幕最靠前的一个命中
      - [buster, arts, quick] # 最后一张兜底全色卡
```

### 从者档案

技能 / 选目标 / 宝具的角色引用统一由从者档案解析，档案位于
`data/servants/<职介>/<名称>.yaml`（目录名须与 `职介` 字段一致）。
新建档案用 `python scripts/servant.py <Mooncell页面名>` 生成骨架
（参数即 `https://fgo.wiki/w/<页面名>`，`--print` 只打印、`--force` 覆盖重建），
生成后只需补三类截图映射：

```yaml
名称: U－奥尔加玛丽 # 图鉴名，与文件名一致；昵称也可被任务引用
昵称: [所长]
职介: UnBeast
角色池目录: 奥尔加玛丽 # target 立绘所在目录：角色池/<此名>/，缺省为 名称

灵基: # 灵衣并入灵基，每条 = 一个可选形态
  - { 名称: U－奥尔加玛丽, 立绘: [1], 技能组: 灵基1-2 }
  - { 名称: 奥尔加玛丽·阿尼姆斯菲亚, 立绘: [3], 技能组: 灵基3-4 }

技能: # 技能号 → 技能池/skill_N；多技能组角色按组分节
  灵基1-2: { 1: 1, 2: 2, 3: 3 }
  灵基3-4: { 1: 1, 2: 2, 3: 3 }

宝具:
  模板: [既已过去的人理之终] # → 宝具/<名>.png，强化改名时并列
```

- 同名不同职介是两个角色（各建档案）；同一技能的多个图标变体（强化前后）
  在技能号下并列列表，任一命中
- 名称 / 昵称全局唯一，重复时加载报错；技能图标、立绘、宝具模板填 `null`
  表示待截图登记，被任务引用到时才报错并提示
- 名称中的全角 `－` 归一化为半角匹配

### 技能条目字段

- `skill` / `master`：二选一。`skill: 角色/技能号`（如 `所长/2`）经从者档案解析为技能池模板，识别区域自动限定为该从者位次的技能栏分区（troop 驱动，表格 region 列显示 `1号位` 等），表格显示为「角色/技能号」；多技能组角色在图标有差异时须写 `角色/技能组/技能号` 消歧；同名多副本用 `N号位` 前缀消歧（如 `1号位所长/2`）。`master` 取 `1` / `2` / `3`，为御主菜单里的第 N 个技能，表格显示为「御主技能<N>」，展开为御主技能图标单击（模板 `基本/御主技能`，打开菜单，region 默认 `右`）+ 命名坐标点 `Master<N>` 直接点击——御主技能位置固定，不走模板识别，坐标在 `task_executor.py` 的 `NAMED_POINTS` 中以 1280×720 为基准填写
- `const`：常量基础步骤——无识别的固定点击，值为命名坐标点（`Enemy1` 等，`Center` 禁写），原样透传为单次点击，不参与动画加速分派
- `target`：可选的子步骤字段（挂在 skill / master 条目上）：本体单击打开目标菜单后，紧接单击选目标，选完自动延后双击（0.5 秒后补第二击）加速动画播放。值为字符串或字符串列表——列表时以 multi 模式取屏幕最靠前的一个命中（与 cards 数组槽位语义一致）。值优先按从者档案解析：`角色名` → 该角色全部已登记立绘（多形态并列任一命中）、`角色名/立绘编号`（如 `奥尔加玛丽/1`）、`角色名/形态名`（按灵基显示名或立绘文件名过滤，如 `摩根/冬之女王`）；不是已登记角色时按原始模板路径 `角色池/<值>` 处理
- `threshold`：匹配阈值，与子步骤语法一致（`index` / `region` 不再支持——分区由 troop 自动生成）

### 回合条目字段

- `skills`：技能条目列表，按序执行（见上「技能条目字段」）
- `cards`：选卡槽位列表，每回合最多 3 个（宝具占其一），每个槽位一次识别点击，按列表顺序执行。槽位三种写法：字符串（单一目标 → `基本/<名>`）、数组（目标范围，`multi` 模式点屏幕最靠前的一个命中）、映射（宝具 `np: 角色名` → 档案宝具模板列表，强化改名并列任一命中；也可直接写宝具模板名 → `宝具/<名>`）。已选中的卡出现选中标记后置信度下降不再命中，槽位间的候选范围可安全重叠。槽位间的点击间隔固定 0.5 秒（攻击按钮点击后保留 1 秒等发牌动画）。解析到 `cards` 即自动先点击右下角攻击按钮进入选卡，无需显式配置，个别界面差异用 `attack_region` 字段覆盖

### 动画加速规则（自动内化）

动画加速不再依赖手写中央点击，技能条目的点击方式按下列规则自动分派：

| 条目类型                 | 点击方式                          | 原因                                           |
| ------------------------ | --------------------------------- | ---------------------------------------------- |
| 无 target 的 skill 条目  | 双击                              | 第一击触发技能，第二击加速动画播放             |
| master 条目（无 target） | 双击 `Master<N>`                  | 第一击使用御主技能，第二击加速动画播放         |
| 带 target 的技能条目     | 本体单击；选完目标延后双击 0.5 秒 | 本体只是打开目标菜单；动画在选完目标后才开始播 |
| const（常量步骤）        | 单击                              | 固定点击，无动画可加速                         |

## 节点图任务（手写，研发中）

**节点图仍在测试研发中，暂不投入使用，现有任务请一律使用 flow。**以下内容
仅作为 flow 展开的目标形态与研发参考。

节点 = 一个画面（识别 + 动作），`next` = 有序候选列表——一帧截图按序尝试候选，
先命中谁走谁。"接下来做什么"由当前画面决定，而不是步骤顺序。

节点 = 一个画面（识别 + 动作），`next` = 有序候选列表——一帧截图按序尝试候选，
先命中谁走谁。"接下来做什么"由当前画面决定，而不是步骤顺序。

```yaml
task_name: 图任务示例
prerequisite: 需要准备指定从者和御主礼装
entry: [选助战]
nodes:
  选助战:
    template: 助战池/选助战
    region: 右
    max_times: 3
    exceeded_next: []
    next: [开始任务]
  开始任务:
    template: 基本/开始任务
    region: 右下
    timeout: 3
    next: [战斗]
  战斗:
    template: 基本/attack
    region: 右下
    action: none
    steps:
      - template: skill_1.png
        double: true
    next: [战斗, 结算]
  结算:
    template: 基本/请点击游戏界面
    region: 下
    next: [结算, 下一步]
```

### 节点字段（除 template 外全部可省略）

- `template`：识别模板；缺省时为无条件节点（如命名坐标点），只能放在候选列表末尾
- `region` / `index` / `threshold`：识别区域、点击第几个匹配、匹配阈值，与子步骤语法一致（`threshold` 默认 `0.7`）
- `action`：`click`（默认，点击识别到的目标）/ `none`（只识别，配合 `steps`）
- `click`：命名坐标点（`enemy1`、`enemy2` 等，`Center` 禁写），无识别直接点击；只在无 `template` 的节点上生效
- `steps`：命中后按子步骤语法顺序执行的子步骤（复用 `task_executor`）
- `next`：候选下一节点列表（一帧截图按序尝试）
- `on_error_next`：出错路由（子步骤失败 / 等待超时且无可选节点），用于自救
- `max_times` / `exceeded_next`：本节点最多命中次数；到达后再出现则走 `exceeded_next` 而不执行动作
- `store_gate` / `store_end`：共享状态仓字段（运行期变量如剩余周回轮数）。`store_gate: 键`：键值 < 1 时该节点视为不存在（同帧继续扫描后续候选，不阻塞路由），命中即把键值递减 1（内置标准周回的连续出击节点用 `remaining`，苹果节点用 `use_apples` / `no_apples`）；`store_end: 键`：声明该字段的节点被**命中**后进入收尾阶段，此后等待无命中持续超过宽限期（约 2 秒）即正常结束本次图执行——对应"结算画面已点完"；命中任何未声明 `store_end` 的节点（选助战、战斗、连续出击等）都会离开收尾阶段，回合操作期间的静默是动画间隙，不参与收尾判断
- `end_reason`：提前结束原因（如内置周回的体力不足收束节点）。命中该节点并执行完动作后，把原因写入状态仓 `end_reason` 键并正常收束本次图执行——worker 读取后做收尾（如回退剩余轮数、上报实际完成轮数）。只识别不点击时配合 `action: none` 使用
- `timeout`：等待本节点的秒数；超时视为"已处理"，直接前往其 `next`（可选节点语义，与子步骤 `timeout` 一致）
- `pre_delay` / `post_delay`：动作前 / 后的等待秒数

### 子步骤语法

节点 `steps` 命中后按顺序执行，每步定义一次识别与动作：

```yaml
steps:
  - template: attack.png
  - template: skill_1.png
    double: true # 双击：第二击加速动画播放
  - template: skill_2.png
    index: 1
    region: "0, 0, 1280, 720"
    step_interval: 1.0
    timeout: 30
  - template: buster,arts,quick
    mode: multi
    count: 2
```

### 步骤字段说明（除 template 外全部可省略）

- `template`：模板图片文件名，默认从 `assets/template/` 中查找；也支持内置命名坐标点，执行时统一解析为固定坐标点击（跳过模板识别）：
  - `Enemy1` / `Enemy2` / `Enemy3`：预设的敌人位置，坐标在 `task_executor.py` 的 `NAMED_POINTS` 中以 1280x720 为基准填写，执行时按实际屏幕尺寸等比缩放
  - `Master1` / `Master2` / `Master3`：御主菜单里的三个技能位置，同样在 `NAMED_POINTS` 中配置；标准周回 flow 的 `master: N` 条目展开时自动使用
  - 命名坐标点也可与普通模板混用在 `multi` 模式的逗号列表中，如 `Enemy1,Enemy2,Enemy3`，解析时拆分为先点击坐标、再识别模板的独立步骤
  - `Center`（屏幕中心）为内部保留常量，yaml 中不允许编写
- `mode`：识别模式，默认 `single`；`multi` 表示同时匹配多个模板, 例如：要在三色卡中任选几张、在不同狗粮中任选20张；`none` 只识别并等待模板出现，不执行点击，适合等待开始标志
- `count`：在 `multi` 模式下，重叠去重后按屏幕位置（上→下、左→右）取前 `count` 个结果依次点击
- `index`：同屏多个匹配时的点击顺序，默认取第一个匹配
- `region`：识别区域，可传 `x1, y1, x2, y2`，也支持 `左`、`右`、`上`、`下`、`左上` 等别名；`1号位` / `2号位` / `3号位` 为从者技能栏分区（标准周回 flow 由 `troop` 自动生成，手写节点图一般用不到）
- `step_interval`：点击成功后等待多久再进入下一步，默认约 `1.0` 秒
- `timeout`：单步识别超时，超过后步骤失败（子步骤失败会触发节点 `on_error_next`）
- `retry_interval` 和 `max_retry_interval`：未匹配到目标时的重试间隔与上限（默认 `0.2` 起步、按 2 倍退避、封顶 `3.0`）
- `double`：`true` 时双击——第一击触发，第二击落在动画播放中加速播放（间隔约 `0.1` 秒）；填数字（如 `0.5`）为延后双击——第一击后延迟该秒数再补第二击（标准周回 flow 的 target 选目标自动使用）；均为展开时自动生成

### 路由与校验规则

- 每轮访问取一帧截图，按序扫描候选节点，命中即执行其动作并路由到它的 `next`
- 等待超时时：优先视为"可选节点已处理"（第一个声明了 `timeout` 的候选直接前往其 `next`），否则走第一个候选的 `on_error_next`，都没有则任务失败
- 用户点击"下一步"（跳过）时：与超时同路；连可选节点和自救边都没有时，兜底视为第一个候选已被手动处理、直接前往其 `next`——跳过只推进图，不会终止任务，且一次点击只跳过一次等待
- 点击成功后立即失效帧缓存，下一轮强制重新截屏
- 加载时静态校验：所有边引用的节点必须存在；无条件节点不能出现在候选列表中间（它不识别就命中，会短路后面的候选）；不可达节点只告警不阻止运行
- `max_times` 到达后节点不再执行动作，仅按 `exceeded_next` 路由；`exceeded_next` 为空列表表示"当它不存在"
- `store_gate` 键值耗尽的节点同帧视为不存在，继续匹配后续候选；`store_end` 节点命中后进入收尾阶段，收尾阶段等待无命中持续超过宽限期即正常结束本次图执行（引擎注入的状态仓需提供 `get(key, default)` / `decrement(key, by)` 两个方法）

## 逃生门

- `type` 字段取值只有 `flow`（内置标准周回展开）和 `nodes`（手写节点图）；
  缺省时视为 `nodes`
- 任务同时写了 `type: flow` 和 `nodes` 时以手写 `nodes` 为准（不展开 flow，仅打印提示）
